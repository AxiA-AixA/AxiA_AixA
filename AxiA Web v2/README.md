# AxiA Web v2

"Axia 전략 수정안 v2"를 반영한 버전이에요. **브리프 합의 툴**입니다. 기존 `AxiA Web`은 그대로 두었어요.

프로젝트를 만들고 레퍼런스를 고르면 공통 태그로 **비주얼 스펙**이 자동으로 만들어져요. 그 스펙을 링크로 보내면 클라이언트가 항목마다 동의하거나, 모르겠다고 하거나, 반대하면서 코멘트를 남길 수 있어요.

## 켜기

1. AI 분석기를 먼저 켜요. `axia-prototype` 폴더의 `Axia-실행-Mac.command`(Windows는 `.bat`)를 실행하세요. 아래 2번 런처를 쓰면 자동으로 켜져요.
2. `AxiA_v2_open.command`(Windows는 `AxiA_v2_open.bat`)를 더블클릭하면 http://localhost:3001 이 열려요.
   - ZIP으로 받은 경우 Mac에서는 처음 한 번 터미널에서 `chmod +x AxiA_v2_open.command ../axia-prototype/*.command`를 실행해야 더블클릭으로 열려요.
   - 런처는 처음에 한 번 빌드(약 1분)한 뒤 빠른 모드로 켜요. 코드를 바꾸면 Mac 런처는 알아서 다시 빌드하고, Windows는 `.next` 폴더를 지우면 다시 빌드해요.
   - 코드를 고치면서 바로 보려면 터미널에서 `npm install` 후 `npm run dev`를 쓰세요.
   - v1(3000번 포트)과 동시에 켜도 돼요.

## 화면

| 주소 | 내용 |
|---|---|
| `/` Projects | 프로젝트 목록과 새 프로젝트(이름 · 클라이언트 · 클라이언트가 쓴 단어, 예: "minimal") |
| `/project/<id>` | 위: 4단계 진행 표시(References → Spec → Client → Agreed brief)와 지금 할 일 버튼 하나<br>왼쪽: 레퍼런스. 링크 붙여넣기, 이미지 업로드·끌어다 놓기, ⌘V 스크린샷, 보관함에서 고르기(Suggested 정렬). 새 이미지는 "Analysing…"으로 보이고, 분석 실패는 눌러서 다시 시도. 지운 건 Undo<br>오른쪽: 비주얼 스펙. 한 문장 요약, 만든 방법(몇 장·몇 개 태그), 클라이언트 단어 확인(레퍼런스에 실제로 보이는지), Clear(60%+)와 나머지(30–59%, 접힘), 필요할 때만 여는 메모<br>아래: Client 단계(링크, 응답 막대) |
| `/project/<id>/agreed` | 합의된 브리프 1장: 합의한 항목, 팔레트, 대표 레퍼런스, 논의할 항목, 응답자·날짜. 인쇄/PDF 저장, 텍스트 복사 |
| `/brief/<token>` | 클라이언트 화면. 가입 없이 항목마다 ✓ 동의 / ? 모르겠다 / ✕ 반대를 고르고 코멘트를 남겨요. 앱 메뉴는 숨겨져 있어요 |
| `/map` | 레퍼런스 맵 (로고를 누르면 열려요). 색·분야·태그·그룹·플랫폼으로 묶고 검색으로 걸러요 |
| `/library` | 레퍼런스 추가 페이지 (`/reference`도 여기로 와요) |

## 데이터

- 프로젝트, 스펙 수정 내용, 클라이언트 응답은 `data/projects.json`에 저장돼요. 클라이언트 이름과 답이 들어 있어서 `.gitignore`로 제외했어요.
- 디자이너 화면은 분석기(8770)에서 이미지를 바로 불러와 빨라요. 클라이언트 화면은 `/api/img/<파일>`을 거쳐서, 이 서버에 접속할 수 있는 컴퓨터라면 어디서든 이미지가 보여요.
- 공유하는 순간의 스펙을 스냅샷으로 저장해요. 이후 스펙을 고쳐도 "Update shared brief"를 누르기 전까지 클라이언트 화면은 바뀌지 않아요. 링크는 같은 주소로 유지돼요.

## 코드 구조

| 위치 | 하는 일 |
|---|---|
| `lib/spec.js` | 레퍼런스 태그로 비주얼 스펙 만들기, 클라이언트 단어 확인, 요약 (순수 함수) |
| `lib/status.js` | 프로젝트 4단계, 다음 할 일, 응답 집계 (순수 함수) |
| `lib/graph/` | 맵: 묶기·검색어(`terms.js`), 쿼드트리 레이아웃(`layout.js`), 썸네일 불러오기(`thumbs.js`) |
| `lib/axia.js` | AI 분석기(axia-prototype, 8770) 연결 |
| `lib/projects.js` | `data/projects.json` 저장 (임시 파일에 쓴 뒤 교체, 깨진 파일은 덮어쓰지 않음) |
| `lib/client/library.js` | 브라우저에서 라이브러리 읽기 (바뀐 게 없으면 304로 본문 없이 응답) |
| `app/Graph.js` + `app/graph/` | 맵 화면. 카메라(`camera.js`), 그리기(`draw.js`), 마우스·터치(`input.js`) |
| `app/project/[id]/` | 프로젝트 화면. `useProject`(불러오기·저장), `useAddReferences`(파일·링크·붙여넣기), 패널 3개 |

- 이미지는 분석기의 `/thumb/<파일>`(긴 변 400px, `axia_data/thumbs/`에 한 번 만들어 둠)로 보여주고, 원본은 상세 보기와 합의 브리프에만 써요.
- 맵의 조정 슬라이더는 주소 뒤에 `?tune`을 붙이면 나와요 (예: `/map?tune`).
- 테스트: `npm test` (스펙·단계·레이아웃·검색어).

## 알려진 한계 (테스트 빌드)

- 지금은 내 컴퓨터에서만 돌아가요. 실제 클라이언트가 링크를 열려면 서버 배포가 필요해요. 임시로는 ngrok 같은 터널로 3001번 포트를 열면 돼요.
- 계정과 로그인이 없어요. 링크를 아는 사람은 누구나 브리프를 보고 답할 수 있어요.
- 태그 카테고리는 `lib/spec.js`의 `CATEGORIES`에 있어요. `axia-prototype/tags.txt`를 고치면 여기도 같이 고쳐야 해요.
- 레퍼런스는 프로젝트 화면(링크 붙여넣기, 파일, ⌘V)이나 크롬 확장 "Axia로 보내기"로 추가해요. 인스타그램 링크는 로그인 벽 때문에 실패할 수 있어서, 인스타는 익스텐션 우클릭이 더 확실해요.
- 스펙의 약한 항목(30–59%)은 기본으로 꺼져 있어서 클라이언트에게 가지 않아요. 켜야 공유돼요.
